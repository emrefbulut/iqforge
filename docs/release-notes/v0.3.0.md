## iqforge v0.3.0

Two releases ago the tool learned to refuse a split it could not make safely.
This one adds the command that tells you what it *cannot* rule out — and the
first repeat of the leakage measurement on a real capture, which is honest about
what it did and did not establish.

### `iqforge audit`

```bash
iqforge audit dataset/                          # a dataset you built
iqforge audit recordings/ --dirname-level 2     # a folder, before building
```

It reports leakage risk and whether a leakage measurement on this data is even
possible, and it trains nothing. Recording disjointness, cross-split window
overlap, which measurable axis separates your classes, the processing gain that
separation has available, and — on a raw folder — whether two recordings claim
the same air time or ship identical data.

**There is no "clean" status, by design.** Findings are `LEAK` (proven, with the
evidence), `RISK`, `PASS/proof` (established from structure, holds for the whole
dataset), `PASS/sample` (held on what was read) or `NOT CHECKED`. The summary
counts unchecked areas separately and never folds them into passes:

```
SUMMARY       0 leaks, 6 passed, 2 risk, 4 not checked
```

Every run ends with a list of what it did not check, and that list cannot be
suppressed. Physical independence of two recordings, channel and multipath
state, and whether an *unmeasured* axis separates the classes are all outside
what any of these checks reach. A tool that people trust when it says "clean" is
a tool that has to never say it.

Two things it is good at. Overlap is decided from sample-index ranges, never
content similarity — two windows sharing half their samples hold them at
different positions once flattened, so a similarity score rates real overlap
like noise. And in a dataset `iqforge` built, cross-split overlap is settled by
*proof*: windows can only overlap within a recording, so recording disjointness
makes it impossible without reading a single window.

The report is fixed-width ASCII so it can be pasted into a paper unaltered;
`--format json` carries the same fields, `did_not_check` included. `--strict`
exits non-zero on `RISK` as well as `LEAK`.

### The leakage measurement, on a real capture

The stride sweep of [methodology §3](https://github.com/emrefbulut/iqforge/blob/main/docs/methodology.md)
was repeated on a public DASH7 capture set — 3 channels, 10 independent recorder
runs each, 150 training runs.

**The zero-overlap null holds.** At stride 1024, where windows share no samples,
inflation is −3.7 pp ± 3.7 — indistinguishable from zero, as on synthetic data.
That is the row the causal claim rests on, and it reproduces outside synthetic
signals.

**The effect size does not.** Inflation rises with overlap and the paired
per-seed trend gives +15.8 pp per unit overlap at t = 2.07, but no individual
row clears t = 2 and only 8 of 15 seed pairs show it. Consistent with the
synthetic mechanism; not independent proof of it.

The reason is a property of that dataset rather than of the experiment, and it
is the fourth entry in the survey below.

### A fourth kind of unsuitable dataset

§6 previously ruled out three public datasets on provenance: none documents
which of its files share an acquisition. DASH7 cabled clears every one of those
bars — ten independent runs per class, reads without conversion, documented
structure — and was downloaded, prepared and trained on.

It fails on the *task*. The class is a carrier offset, the offsets are 2.33 MHz
apart, and each channel occupies 19.5 kHz of a 7.68 MHz capture: a measured
25.9 dB of processing gain, so the recordings as captured and the same task at
0 dB wideband SNR both classify at 100.0%. The usable band turns out to be about
7 dB wide, with the same arm scoring 37.4% and 79.7% on two seeds.

So the search criteria are four, not three: real hardware, documented
independence, a readable format, and **a task whose difficulty is graded**. Only
the first three can be checked before downloading anything — which is most of
why `audit` exists. Pointed at those same 30 recordings it returns the verdict
that a 1.6-hour training grid was about to reach, in eight seconds:

```
VERDICT       ceiling - carrier offset alone classifies 100% of recordings
              (chance 33%), so a trained model will saturate and leave no room
              to measure a leak
NEXT          do not run measure-leakage on this data.
```

### Also

`scripts/audit_leakage.py` now documents that its cosine-similarity twinning
check is blind to offset overlap — it finds exact duplicates and nothing else,
while every real case is a partial overlap. It is left as it stands, with the
limitation stated in its output; `iqforge audit` does not inherit it.

### Install

```bash
pip install --upgrade 'iqforge[torch]'
```

Python 3.11+. `torch` is optional; `info`, `inspect`, `build`, `stats` and
`audit` all work without it. Datasets built by `0.1.0` and `0.2.0` are still
readable.
