## iqforge v0.2.0

Everything in this release came out of pointing the tool at real public
datasets and finding out where it was quiet when it should not have been.

### Keeping non-independent recordings together

`--group-by` is the counterpart to `--balance-by`. Balancing spreads a nuisance
variable **across** splits; grouping holds related recordings **together**,
because separating recordings that are not independent of each other leaks in
exactly the way recording-level splitting exists to prevent.

```bash
iqforge build data/ -o ds/ --group-by 'path:(loc\d+)/gw_(\d+)_'
iqforge build data/ -o ds/ --group-by csv:units.csv
```

Recordings sharing a key become one indivisible unit, and the unit replaces the
recording as the thing allocated. On a 30-recording public capture set, 10 of 15
same-channel pairs were separated across splits without it and none with it.

Grouping wins any conflict with `--balance-by`: holding non-independent
recordings together is a correctness constraint, spreading a nuisance variable
is a quality one. A unit whose members disagree on the balancing field is marked
`(mixed)`, and `stats` reports how many there are — a run where most units are
mixed is a run where balancing has nothing left to work with.

### Labelling that says what it found

- `--dirname-level` chooses which ancestor directory `--labels dirname` reads.
  A layout like `CH0/rec1/` was silently labelling by the run number.
- A warning when the chosen level looks like a run counter *and* another level
  offers real class names. Numbered classes such as `device_01` or `snr_10` stay
  quiet, because a warning that cries wolf is worse than none.
- When `--labels annotations` finds nothing, the error now reports how many
  annotations were scanned, how many carry `core:label`, and which other keys
  hold text. Behaviour is unchanged: `core:label` is still the only field read,
  and the message says so rather than guessing.

### Catching disagreements between metadata and data

- A warning when an annotation claims samples the file does not contain.
- `manifest.json` carries a `manifest_schema` number, starting at `1`. A
  manifest written by a newer version is refused rather than read optimistically,
  since a later format may record a constraint this version does not know to
  look for.

### Fixed

`iqforge info` reported the reader's SigMF version rather than the recording's.
`SigMFFile(metadata=...)` mutates the dict it is handed and overwrites
`core:version`, so real captures declaring `1.0.0` were shown as `1.2.6`. Both
are now shown when they differ. Reported upstream as
[sigmf/sigmf-python#159](https://github.com/sigmf/sigmf-python/issues/159).

### Measurement

[`docs/methodology.md`](https://github.com/emrefbulut/iqforge/blob/main/docs/methodology.md)
documents how the split claims were measured, what the numbers do not cover, and
why the leakage measurement could not be repeated on real data — three datasets
were assessed and each ruled out, none of them documenting which of its files
share an acquisition.

The `ci8` and `ci16_le` paths were checked against the raw bytes of three public
recordings (exact ÷128 and ÷32768, correct I/Q order).

### Install

```bash
pip install --upgrade 'iqforge[torch]'
```

Python 3.11+. `torch` is optional; `info`, `inspect`, `build` and `stats` work
without it. Datasets built by `0.1.0` are still readable.
