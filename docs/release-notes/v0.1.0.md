## iqforge v0.1.0 — first release

Turn SDR captures (SigMF) into PyTorch datasets, split so the numbers mean
something.

### Why

Splitting IQ windows at random puts neighbouring windows in both train and test.
Reported accuracy goes up, the model gets worse, and nothing warns you. `iqforge`
splits at the **recording** level instead, stratified by class — and when that is
not possible it stops with an error rather than falling back to a split that
would inflate the result.

### What's in it

- SigMF reading (`cf32_le`, `ci16_le`, `ci8`), large files memory-mapped
- Terminal spectrogram inspector
- Fixed-length windowing with configurable stride, no padding, no partial windows
- Labelling from SigMF annotations, directory names, or a CSV
- Recording-level stratified splits, plus `--balance-by <sigmf-field>` to spread
  nuisance variables such as carrier frequency across splits
- Sharded dataset export with a manifest recording config, label map, source
  files and split assignment — same seed, same bytes
- `IQForgeDataset` and a baseline CNN behind `iqforge train`
- 16 example recordings so everything above runs without hardware

### Install

```bash
pip install 'iqforge[torch]'
```

`torch` is optional — `info`, `inspect`, `build` and `stats` work without it.
Plain `pip install iqforge` is enough to build datasets.

### Requirements

Python 3.11+.

### Known limitations

- The `ci16_le` and `ci8` conversion paths are covered by synthetic tests but
  have not been verified against a real capture from hardware. If `iqforge`
  misreads a recording from your SDR, that is the most useful bug report you can
  file — please attach the `.sigmf-meta`.
- Labelling is time-based, so signals that overlap in time but are separate in
  frequency cannot be told apart. Windows spanning more than one annotation are
  dropped and counted, never silently assigned.
